# 所往 SUOWANG — 当前产品简报

当前开发线：`0.2.0-beta.3`。本轮收敛桌面大窗口自适应、事项区余高分配与左侧品牌视觉，不扩张产品模型；当前公开版本仍以 GitHub Releases 为准。

> **行有所往。知所往 · 择其径 · 行其事。**

## 一句话定义

SUOWANG 是人生主线驾驶舱。它让用户在认知余量不足时，看清自己所处的模式、当前主线与下一步；如果仍然难以启动，就把事项降成一个足够容易迈出的最小一步。

## 核心模型

用户只需要理解三个实体：

```text
模式 → 主线 → 事项
```

系统永久只有恢复、工作、生活三个模式。每个模式独立拥有 1–3 条进行中主线、一个当前主线指针、一个下一步指针、一个可选的行动中事项指针、不归入主线的其他事项和 cue。

主线是阶段性使命，不是永久主题，包含主线名称、主线目标、本阶段完成标准和可选低精度本阶段时间范围。多条主线可以进行中，但一个模式同一时刻只有一条当前主线。切换当前主线只改变指针，不结束旧主线，也不制造行迹。同一模式的进行中主线不可同名；不同模式和已经结束的行迹可以同名，主线身份由 ID 而不是名称决定。

事项可以属于某条主线，也可以作为其他事项留在模式中。每条事项由必填的事项名称和非必填的最小一步组成，并可选择为一次事项或持续事项。一次事项完成后进入行迹；持续事项每天最多记录一次，保留累计次数但继续进行中。下一步只能引用当前主线事项或其他事项；指针失效或持续事项当天已经完成时，系统依次选择当前主线第一条可做事项、其他事项第一条、空。

## 第一屏

```text
┌────────左侧栏────────┬─────────────────────────────┐
│ 驾驶舱               │ 问候              日期 · 口号 │
│ 行迹                  ├─────────────────────────────┤
│ 设置                  │ 无边框三岔大道背景 + 模式 Tab   │
│ 显示名称              │ [主线槽 1][主线槽 2][主线槽 3] │
│ 行有所往。            │ 当前主线事项 | 其他事项 | 下一步 │
└───────────────────────┴─────────────────────────────┘
```

道路是品牌签名，也是驾驶舱上半部的连续环境背景，不使用边框、圆角或图片卡片留白。桌面只缩小道路的网页展示窗口并优先裁去少量顶部天空，原图片资产保持不变，分叉、箭头和模式入口必须完整。主线槽作为轻量 Dock 压住背景下沿。当前模式、当前主线和下一步获得明显强调，其余界面安静。右侧 `page-stage` 是唯一页面级纵向滚动容器，在 DevTools 底部停靠、RDP 和小窗口下都必须滚到最底。问候、日期和口号直接位于天空、无顶栏，向下滚动时自然消失；“晚上好”使用月亮图标。

## 关键交互

- 点击主线卡立即设为当前主线。非当前卡不显示“进行中”，当前卡依靠选中样式并辅以低存在感“当前主线”；更多操作使用几何居中的横向三点菜单。
- 主线、事项名称和最小一步原地编辑。
- 事项行显示“事项名称 ｜ 最小一步”；未填写时不显示分隔符。
- 添加事项时可选择“持续”。持续只是事项属性：名称前不放标签，只在完成按钮旁以低存在感的 `↻ N` 显示累计次数；今天完成只改变完成按钮，不给整行染色。事项右键生命周期文案统一为“完成事项 / 放弃事项 / 删除事项”；持续事项可额外撤回今天，一次事项可额外设为持续事项。
- 下一步未开始时显示「开始这一步」；点击后保存行动中事项指针，卡片变为“正在走这一步”，并提供彼此独立的「暂停」与完成操作。暂停只回到未开始界面，不修改事项事实。淡蓝色出发动效只在下一步卡内部掠过，不追踪时长，也不把事项改造成“执行中”状态。
- 下一步右上角的「卡住了？」会原地接管整张下一步卡片，再点即可收拢；它提供四种调整：把步幅降得更小、换一件事项、重新看看主线，或先切到恢复模式。下一步不重复显示所属主线，也不参与拖动。它调整的是步幅、动作、方向和模式，不把启动困难解释成意志问题。
- 主线卡在同模式三个槽之间拖动，空槽移动、已有槽交换。
- 事项整行拖动可以排序、改归属或设为下一步；不会跨模式。
- 主线完成或放弃时，未完成事项默认 abandoned，也可逐条移到其他事项或同模式另一主线。
- Hard delete 用于纠错，必须确认；删除主线时，所属事项默认先移到其他事项。

## 行迹和设置

行迹只按结束时间倒序展示 completed/abandoned 事实。持续事项日常记录不会制造行迹，只有明确“完成事项”或“放弃事项”后才进入行迹，并保留累计次数。行迹事项可撤回为 active；原主线仍 active 时回到原主线，否则回到同模式其他事项。行迹主线可展开，并复制为新的独立主线；新主线不复制旧事项。

设置只包含显示名称、本地头像、三个模式 cue、桌面「工作区空间」、SQLite/JSON 导出和整库恢复。工作区空间提供小、中、大、最大四档：它只通过网页真实裁去道路顶部天空来让出事项空间，默认小；批准道路图、箭头、Dock 的搭桥关系和手机布局不受改写。

## 技术与隐私

当前核心使用 Vanilla JS + CSS + Node HTTP + SQLite；普通用户版以安全 Electron 薄壳提供独立桌面窗口，源码/npm 继续保留 Node 22/24 浏览器入口。Electron 不改变产品模型、HTTP API 或 SQLite 真源。业务数据只存在本机，没有登录、云同步、远程数据库、遥测或运行时 AI。正式数据库从空人生数据开始；demo 与测试使用独立临时库。

邀请测试不改变这一边界：应用不会自动上传使用记录、反馈或数据库。自动备份保存在同一设备，只提供本地恢复能力，不构成异地灾备；用户应通过设置页导出 SQLite 后自行保存在另一设备或可信位置。

内部数据库与 API 为兼容既有数据继续使用 `states`、`todos`、`current_mainline_id` 和 `priority_todo_id` 等稳定标识；这些实现名不进入用户界面。

## 完成闸门

- 2560×1440 和 1920×1080 下，核心驾驶信息单屏可见。
- 320px 下无关键遮挡或横向溢出。
- 重启恢复上次模式、三个槽位、当前主线、下一步和事项顺序。
- 旧数据库自动增加最小一步、事项类型与持续完成记录结构且不丢失既有事项。
- 完成事项后下一步正确接棒。
- 持续事项同一自然日最多记录一次，撤回今天和累计次数可验证。
- 每日备份、导出和覆盖恢复可验证。
- 旧数据库升级前存在独立迁移前备份；迁移失败不留下半升级状态。
- 单元测试、浏览器测试和 smoke 使用独立临时数据目录，不打开个人数据库。
- 日常使用不需要手动运行 `npm start`。
